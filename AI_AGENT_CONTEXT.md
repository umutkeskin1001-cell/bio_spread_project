# AI Agent Context — Cassiopeia

This document provides the full context an AI agent needs to understand this repository when analyzing it through gitingest or similar tools. Many critical files (datasets, features, checkpoints) are gitignored, so this file explains what they contain.

---

## 1. Project Overview

Cassiopeia is a lightweight, DNA-only plasmid risk prediction model that jointly predicts:
- **Mobility** — 3-class: non-mobilizable (0), mobilizable (1), conjugative (2)
- **AMR** — Binary: carries antimicrobial resistance genes (1) or not (0)
- **Expansion** — Binary: present in ≥15 countries (1) or not (0)

Input: raw FASTA DNA → multi-scale canonical k-mer features → neural network → predictions + evidence scores.

## 2. What is gitignored (and why)

### All `.pt` files
Exception: `artifacts/**/*.pt` (trained checkpoints are committed via the exception rule).

### `data/dna_sentinel/*.jsonl` and `data/dna_sentinel/*.fa`
These are dataset splits (train/val/test json lines) and query FASTA files. They are generated by `dna-sentinel prepare` (which reads from gitignored `data/project_inputs/raw/` and `data/project_inputs/silver/`). You must run the pipeline to recreate them; they cannot be committed.

### `data/dna_sentinel/*.pt` (features and labels)
Generated by `dna-sentinel prepare-features`. Contains:
- `{split}_features.pt` — dictionary with keys:
  - `"features"` — Tensor `[N, 28, 2728]`, float32, multi-scale canonical k-mer counts (L2-normalized per window)
  - `"struct_features"` — Tensor `[N, 28, 19]`, float32, structural features (GC content, dinucleotide composition, etc.)
  - `"masks"` — Tensor `[N, 28]`, bool, which windows are valid (padded windows are False)
  - `"scale_ids"` — Tensor `[N, 28]`, int64, which scale (0/1/2) each window belongs to (INFO: currently unused by model)
- `{split}_labels.pt` — dictionary with keys:
  - `"mobility"` — Tensor `[N]`, int64, values 0/1/2
  - `"amr"` — Tensor `[N]`, float32, values 0.0/1.0
  - `"expansion"` — Tensor `[N]`, float32 (binary) or int64 (multi-class)

### `data/project_inputs/raw/`, `silver/`, `external/`, `scores/`, `geo_spread/`
Parent project data bundle. Contains raw PLSDB FASTA, backbone tables, AMR tables. Not tracked because these are large bioinformatics files. `data/project_inputs/README.md` explains the bundle.

## 3. Dataset & Training

### Pipeline steps
```
prepare (parse FASTA + build labels + group-aware split)
  → prepare-features (extract k-mer features for each split)
  → train (train model, evaluate, calibrate)
```

### Group-aware splitting (`src/dna_sentinel/prepare.py`)
- Uses Disjoint Set Union (DSU) to cluster sequences by:
  1. Exact prefix match on first 1000 bp (SHA256 hash)
  2. Backbone ID group membership
  3. Jaccard similarity ≥0.80 on sampled 15-mers
- Clusters are split into train/val/test to prevent label leakage

### Feature extraction (`src/dna_sentinel/features.py`)
- Three window scales: 512 bp (16 windows), 2048 bp (8 windows), 8192 bp (4 windows) = 28 total
- Strides: 256, 1024, 4096 (overlapping windows)
- Canonical k-mer counts (k=4..6) with reverse-complement collapsing (total vocab size: 2728)
- Features are L2-normalized per window (baseline 1e-6 to avoid NaN in float16)
- Structural features: GC content, GC skew, AT skew, 16-dim dinucleotide composition (19 total)

### Current dataset
| Split | Size |
|-------|------|
| Train | 1,414 |
| Validation | 280 |
| Test | 354 |
| Held-out test | 1,200 |

## 4. Model Architecture Details

### Forward Pass
```
kmer_features [B, 28, 2728]  (float32)
  → FRP (2728→256): deterministic ternary matrix (≈1/6 each of +1, -1; ≈2/3 zero)
  → F-LoRA: low-rank correction (rank 8)
  → Bottleneck: LayerNorm → Linear(256→128) → GELU
  → ContextGate: per-window gating using global context vector
  → 2× GLUMixer: token mixing (window axis) + channel mixing (feature axis)
  → [stochastic depth on each mixer during training, drop_path_rate=0.1]
```

### Evidence Pooling
```
shared features [B, 28, 128]
  → task adapters (mob/amr/exp: bottleneck 128→8→128)
  → MultiQueryEvidencePool: attention-weighted sum over windows
  → task heads
```

### Task Heads
- **Mobility**: Linear(128→3), trained with cross-entropy + label smoothing (0.1)
- **AMR**: Linear(128→1), trained with focal BCE (γ=2.0)
- **Expansion**: Linear(128 + mob_logits + amr_logits → 1), trained with focal BCE (γ=2.0)
  - The expansion head conditions on mobility and AMR logits (detached to prevent gradient shortcutting)
- **Deep supervision**: Aux classification heads on intermediate mixer output (w_aux = 0.3)

### Loss
Uncertainty-weighted multi-task loss:
```
loss = Σ_i [0.5 * exp(-log_var_i) * loss_i + 0.5 * log_var_i]
```
where `log_var_i` are learned per-task log-variances (clamped to [-6, 6]).

### Calibration
After training, Platt scaling is applied:
- Mobility: temperature scaling (learned scalar `t`)
- AMR: Platt logistic regression (learned slope `w`, intercept `b`)
- Expansion: Platt logistic regression (learned slope `w`, intercept `b`)

### Training
- Optimizer: AdamW (backbone 3e-4, head 3e-4, weight_decay 0.05)
- Scheduler: 5-epoch linear warmup → cosine decay to 1e-5
- Gradient clipping: 1.0
- Gradient accumulation: 2 steps
- Batch size: 32
- Mixup: manifold mixup (α=0.3) on hidden representations (not inputs)
- Early stopping: 25 epochs patience
- 100 max epochs

## 6. Key Design Decisions

1. **No scale embeddings** — Model learns scale from position alone (ablation showed scale embeddings hurt by -1.6% Mob BA)
2. **Single evidence head** — Multi-query with 4 heads hurt by -3.1% Mob BA vs single head
3. **F-LoRA > plain FRP** — LoRA correction improves Mob BA by +2.8% over pure FRP
4. **Manifold mixup** — Mix hidden states (not inputs); helps Exp +2.7% but neutral on other tasks
5. **Detached logits in expansion head** — Prevents gradient shortcutting through mobility/AMR → expansion path
6. **FRP is deterministic** — Same seed → same matrix. Matrix regenerated at load, not stored in checkpoint
7. **compute_loss exists but unused in training** — Loss is computed manually in train.py for flexibility with mixup
8. **scale_ids saved but unused** — features.py still saves scale_ids tensor; model ignores it

## 7. Known Gotchas

- `test_augmentation.py` imports from `pipeline` may break if not updated (pipeline.py was deleted)
- MPS backend: avoid large float32 tensors; stochastic depth bernoulli is fp32 safe
- `features.py` normalize uses eps=1e-6; too small for float16 but features are stored in float32
- Non-deterministic hash in prepare.py was fixed (uses `hashlib.md5` now instead of `hash()`)
